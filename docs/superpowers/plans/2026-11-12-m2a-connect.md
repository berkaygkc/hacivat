# M2a "Connect" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the M1 shell into an app that saves, tests and opens connections to PostgreSQL 14–18, MySQL 8.0/8.4, MariaDB LTS and SQLite. That means:
- native drivers behind one `Driver` trait;
- profiles in `connections.toml`, with secrets in the OS keyring;
- URL paste in both directions;
- an ordered connect pipeline with honest error classes and quick fixes;
- the approved M2a connection-flow UI, in EN and TR, through Fluent.

**Architecture:** M2a adds eight core crates under `crates/core/` and one test-support crate:
- `hacivat-proto`: shared ids and enums.
- `hacivat-net`: byte streams, direct transport, the loopback forwarder, and non-interactive TLS.
- `hacivat-secrets`: keyring store, retention, scrubbing, pgpass/pg_service, and auth providers.
- `hacivat-driver`: the `Driver` trait, engine catalog and registry, URLs, sanitizing, and error classification.
- `hacivat-driver-pg`, `hacivat-driver-mysql`, `hacivat-driver-sqlite`.
- `hacivat-session`: the core Tokio runtime, profiles and their store, the connect pipeline, test connection, `ConnectionManager`, and the budget seam.
- `hacivat-testkit`: Docker targets, used by tests only.

The app gets a `connections/` module that joins these crates to new `hacivat-ui` primitives through shell hook slots. Core crates never see UI types. UI crates never see core types. The app is the only place where both meet (§5.1, enforced by `xtask check-deps`).

**Tech Stack:**
- Everything from M1: Rust 1.98.1, edition 2024, GPUI fork `4858c09`, Fluent and ICU4X, `jiff` 0.2.38.
- Runtime: `tokio` 1 (rt-multi-thread, net, time, sync, macros, io-util), `tokio-util` 0.7 (`CancellationToken`), `futures` 0.3.
- Drivers: `tokio-postgres` 0.7, `mysql_async` (latest 0.3x; T14 records the feature set), `rusqlite` (latest 0.3x with features `bundled` and `column_metadata`).
- TLS: `rustls` 0.23 with the `ring` provider (not aws-lc-rs), `tokio-rustls` 0.26, `rustls-platform-verifier`, `rustls-pki-types` (PEM).
- Secrets: `keyring` 3 with `apple-native`, `windows-native`, `async-secret-service`, `crypto-rust` and `tokio`; `secrecy` 0.10; `zeroize`.
- Data: `uuid` 1 (v4, serde), `url` 2, `percent-encoding` 2, `regex` 1.
- Dev-only: `rcgen` (test certificates) and `tempfile`.
- Exact versions are whatever is current and compatible when Task 1 adds them; the record is `Cargo.lock`. Any other crate needs a ruling.

- **Dependencies (F23).** Task 1 writes every new manifest with every dependency M2a needs. A later task never edits a manifest it does not own. Exceptions: Task 14 may edit `deny.toml` (R18), and the controller adds one-line fixes. **Never run a plain `cargo update`** (M1 Task 15 lesson: it downgrades `windows-sys`). Add a dependency by editing the manifest and running `cargo check`, which adds only the new lock entries. If a precise bump is needed, use `cargo update -p <crate> --precise <v>`.

- **Secrets.** These are hard rules:
  - A password, passphrase or key never appears in `connections.toml`, `settings.toml`, `workspace.json`, logs, panic messages, `Debug` output, Display or Copy URLs, the clipboard (except an explicit "copy with password", which M2a does not offer), or test snapshots.
  - Secrets travel as `secrecy::SecretString` and are zeroized on drop.
  - Keyring calls run only on the Tokio blocking pool, never on the UI thread.
  - The keyring is never touched at startup. A secret is read only when a connect needs it.
  - Dev builds use the `hacivat-dev/` keyring service prefix (R7) and never a plaintext store.
- **Threading (§5.4).**

  - GPUI foreground tasks await only `tokio::sync` channels (`oneshot`, `watch`, `mpsc`).
  - Tokio I/O types are never polled outside that runtime.
  - The UI thread never awaits I/O.

## Review Focus

1. **Pasted and copied connection strings carrying secrets.** Users paste many kinds of strings:
   - URLs whose password contains `@ : / %`;
   - IPv6 hosts and non-ASCII database names;
   - `jdbc:` prefixes, surrounding whitespace and newlines;
   - input over 64 KiB;
   - a password that happens to look like a URL, pasted into the Password field.

   The expected behaviour: the password is split off and is never written to `connections.toml`, logs or the clipboard. Copy as URL never contains it. Pasting into the Password field inserts the text literally.

   Tests: `display_and_copy_never_contain_the_password` (Task 3), `url_paste_edge_vectors` (Task 7), `paste_into_password_field_is_literal` (Task 17), `connections_toml_never_contains_a_secret` (Task 12), `connect_logs_never_contain_the_password` (Task 16).
2. **Hand-edited or foreign `connections.toml`.** Expect duplicate or missing ids, an unknown engine, a `password = "…"` key that a user typed in, a newer format version, unknown keys, or text that does not parse. The app starts with what it can read. It quarantines an unparsable file. It never echoes or re-writes a typed password. It keeps unknown keys. It refuses to write a newer major version.

   Tests in Task 12: `password_key_typed_into_file_is_ignored_and_reported`, `unknown_keys_are_preserved_on_save`, `newer_version_is_read_only`, `unparsable_file_is_quarantined`, `duplicate_ids_keep_the_first`.
3. **Turkish input and Turkish servers.**
   - Host and profile names with `İ`/`ı`.
   - Option keys such as `applİcation_name`.
   - A PostgreSQL server that answers `ÖLÜMCÜL … parola doğrulaması başarısız`.

   Classification follows the code; matching uses ASCII folding only; and production suggestion matches ASCII `prod|prd|live` only.

   Tests: `code_beats_localized_text` (Task 10), `option_keys_fold_ascii_only` (Task 2), `dsn_keys_fold_ascii_only` (Task 7), `prod_suggestion_ascii_only` (Task 12), `turkish_server_wrong_password_is_auth_invalid` (Task 19).
4. **The keychain is unavailable, denied, slow or too small.** Cases: the macOS Keychain is locked and the user clicks Deny; Linux has no Secret Service; a Windows blob is over 2,560 bytes; a keychain dialog takes 20 s. The app never blocks the UI thread. It falls back to keeping the secret for this session, with one honest toast. It never writes plaintext. A keychain prompt does not count toward the connect timeout until it returns (HV-CONN-01 edge case).

   Tests: `keyring_denied_falls_back_to_session_with_reason` and `windows_blob_limit_falls_back` (Task 4); `slow_secret_lookup_does_not_count_toward_timeout` (Task 16); `secret_ops_never_run_on_the_ui_thread` (Task 12).
5. **Connect-lifecycle races.**
   - Esc while connecting; closing the dialog while a test runs.
   - Double-click connect.
   - Deleting or editing a profile while it connects.
   - Quitting during a connect.
   - A driver that completes after the timeout.

   The expected behaviour: one attempt per profile (single-flight); cleanup runs LIFO; late connections are closed; a deleted profile's session secrets are forgotten; quitting closes everything within 2 s.

   Tests: `cancel_mid_connect_runs_cleanups_lifo`, `concurrent_connects_single_flight`, `late_connection_after_timeout_is_closed`, `shutdown_closes_all_within_budget` (Task 16); `delete_while_connecting_cancels_and_forgets_secrets` (Task 18); `closing_dialog_cancels_running_test` (Task 21).

## Assumptions and rulings

These are controller calls made while the PO is away, and the PO can overrule each one. Each says why, and what it costs if it is wrong.

- **R1. Crate set and placement.**
  - New crates: `hacivat-proto`, `hacivat-net`, `hacivat-secrets`, `hacivat-driver`, `hacivat-driver-{pg,mysql,sqlite}`, `hacivat-session`, and `hacivat-testkit` (dev-only).
  - The `hacivat-core::core::*` paths in `alg/01` map to the canonical §5.1 crates:
    - `caps`, `driver`, `url`, `sanitize`, `errors` → `hacivat-driver`;
    - `conn::pipeline`, `conn::test`, `conn::singleflight`, `session::manager` → `hacivat-session`;
    - `secrets::{store,files,providers,export}` → `hacivat-secrets`;
    - `net::{tls,direct,forwarder}` → `hacivat-net`.
  - There is no `hacivat-core` facade yet (§8 item 4). There is no `hacivat-guard` and no `hacivat-values` until M2b/M3.
  - *Cost if wrong:* moving modules later.
- **R2. ID numbering.** L15 names "TLS Auto flows (HV-SEC-01 …)" and "SSH (HV-SEC-02)", but `alg/01` numbers SSH as SEC-01 and TLS as SEC-02 (Register Appendix B #10 already flags these cross-references). This plan follows `alg/01`'s numbers and L15's content.
- **R3. TLS in M2a is the non-interactive half of D-005 (HV-SEC-02).**
  - **M2a has:** modes Disable/Auto/Require/VerifyCa/VerifyFull, a CA file, a client certificate with an unencrypted PEM key, the platform verifier, TLS 1.2 minimum, and the permanent "unencrypted" badge.
  - **`Auto`:** verify whenever the server offers TLS. Plaintext is allowed only for loopback, RFC 1918/4193 private addresses and Unix sockets, and then the badge shows. A public host without TLS fails with `tls.not_supported_by_server`. An untrusted chain fails with `tls.untrusted`, and a name mismatch with `tls.hostname`.
  - **Interim quick fix:** "Encrypt without verifying" (`FixId::EncryptWithoutVerifying`, string `hv-conn-fix-require`) sets the profile's mode to Require and connects. It is honest, and the user chooses it. The capsule and the sheet then say `TLS 1.3 · not verified` (`hv-conn-enc-unverified`, new string, PO review).
  - **M2b:** pinning, CA import from the prompt, and the "public host without TLS" ask dialog. M2b re-evaluates the interim fix.
  - *Why:* Docker MySQL 8.x and MariaDB 11.4 ship self-signed certificates, so without this fix M2a could not reach a default local MySQL in `Auto`.
  - *Cost if wrong:* one fix id and one string removed in M2b.
- **R4. No UI shells for the TLS certificate dialog or the SSH settings in M2a.**
  - The connection dialog has no SSH disclosure. The `network.dns` error offers no "Connect through SSH…".
  - `TransportSpec::SshTunnel` is reserved; Validate rejects it with `config.invalid` / `IssueCode::TransportUnavailable`.
  - *Why:* "Trust is visible". A control that does nothing misleads, and a shell would be tested twice. The disclosure list is data, so M2b adds the designed rows without changes elsewhere.
  - *Cost:* none beyond M2b's planned work.
- **R5. The Linux master-password vault goes to M2b, not M9.**
  - M2a ships the `VaultBackend` trait only.
  - On Linux without Secret Service, "Forever" falls back to "Until restart" with one `hv-conn-keyring-unavailable` toast. The Remember Select shows Forever as disabled, with a hint.
  - *Why M2b:* the unlock prompt reuses the `Interaction` plumbing that M2b extends for SSH passphrases, host keys and TLS pins. Linux users start daily use in M3. HV-SEC-05's "vault on CI Linux" test belongs with secrets, not with release hardening.
  - *Cost:* until M2b, Linux users without a keyring retype passwords after a restart.
- **R6. Linux keyring.** Use `keyring` with `async-secret-service` + `crypto-rust` + `tokio`: pure-Rust zbus, no libdbus. Task 4 verifies the Linux build in CI. Linux keyring round trips are manual (no D-Bus session in CI).
- **R7. Keyring entries and dev signing.**
  - The service is `hacivat/<profile-uuid>/<slot>`, or `hacivat-dev/<profile-uuid>/<slot>` when `cfg(debug_assertions)`. The account is `hacivat`.
  - Slots: `db-password`, `tls-key-passphrase`. `ssh-<hop>-password`, `ssh-<hop>-passphrase` and `proxy-password` are reserved.
  - Dev builds avoid repeated macOS Keychain prompts by signing with a stable local identity:
    - `scripts/dev-sign.sh --create-identity` makes a self-signed "Hacivat Dev" code-signing identity in the login keychain, once.
    - `scripts/dev-run.sh` (the macOS cargo `runner` in `.cargo/config.toml`) signs the binary with `--identifier dev.hacivat.app` and runs it.
    - Without the identity, it prints one hint and runs the binary unsigned. It never fails.
  - Windows Credential Manager blobs over 2,560 bytes raise `SecretError::TooLarge`, and the store falls back to UntilRestart.
- **R8. Retention.**
  - The default is Forever (PO Q4).
  - *Save* stores the draft password according to its retention: Forever → keyring, UntilRestart → memory, ForSession → held for the next session, Never → dropped.
  - Test connection never stores anything.
  - A password re-entered after `auth.invalid` is stored only after a successful connect (HV-SEC-03 step 4).
  - Lowering the retention deletes the keyring entry at save.
- **R9. One profiles file.**
  - `connections.toml` (§5.6), `version = 1`, UUID ids. There is no `connections.local.toml` split; portable export is v1.x (C16).
  - Unknown keys are preserved (toml_edit). A newer major version makes the store read-only, with no writes and a toast. An unparsable file is quarantined like settings.
- **R10. Read-only in M2a is a label plus a minimal session setting.**
  - The sheet and the capsule tooltip say "read-only (guarded)".
  - PostgreSQL gets `-c default_transaction_read_only=on`. MySQL/MariaDB get `SET SESSION TRANSACTION READ ONLY` at PostConnect. SQLite opens with `SQLITE_OPEN_READONLY`.
  - `AccessLabel::ReadOnlyEnforced` exists but is never produced.
  - `hacivat-guard`, the role probe and the "enforced" label come in M2b.
  - MariaDB stays "guarded" (C19).
- **R11. Unsupported servers (PO Q3).**
  - Below the floor, the result is `server.unsupported_version` at CheckServer, with fixes `[SupportedVersions, EditConnection, ConnectAnyway]`.
  - ConnectAnyway persists `allow_unsupported_server = true` on the profile. From then on, the capsule, status bar and sheet carry an "unsupported" mark (`hv-capsule-unsupported`, new string) for as long as the server is below the floor.
  - "Supported versions" opens `https://hacivat.dev/docs/engines`. This is a placeholder URL and an open item for the PO.
- **R12. HV-CONN scope.**
  - CONN-01, -03 and -07 ship in full.
  - CONN-04: `RawConn::ping`, plus a fixed liveness ping (`ManagerConfig::liveness`, 30 s) that marks a live connection `Lost`. The capsule then shows Failed with Retry. The keep-alive interval is stored and shown. The supervisor tick, sleep/wake handling and idle disconnect come in M2b.
  - CONN-05 (reconnect, backoff, state replay, and the D-085 "session lost" toast) comes in M2b.
  - CONN-02 comes in M4, with its first consumer, per-database introspection. "Use <db>" edits the profile's database instead.
- **R13. Budget seam (D-035).**
  - `hacivat-session::budget::Budget`: 4 for remote engines and 1 for SQLite.
  - The main connection takes one permit. Test connections take none, because they use fresh resources (CONN-07).
  - The SessionManager in M2b consumes it. Advanced states it as a fact ("Up to 4 open at once").
- **R14. Interaction.**
  - `UiPort::ask(Question) -> Answer` is async.
  - M2a asks only `Question::Password`, through a 480 px password dialog that reuses the error dialog's re-entry field.
  - In `Headless` mode, a missing secret fails with `ConnectError::needs_interaction = true` and no prompt.
- **R15. l10n carry-overs from the M1 ledger.**
  - A new documented variable type `(Decimal)` generates an `ExactDecimal` field, for durations such as `0,06 sn`. `(Number)` stays `Count`, so M1 call sites don't churn. The settings preview drops `t_dynamic` for the typed ID.
  - `PreparedQuery` (the search key of a query, built once) lands with the explorer filter (Task 18).
  - Any `WhenValue::Instant` goes through the `jiff` path. M2a formats no instants.
  - L026 (registry codes without English messages) is implemented over `errors.toml` (Task 10).
- **R16. Duration copy.**
  - Totals and pings are whole milliseconds: `Connected in 54 ms`.
  - Running clocks show seconds with 2 decimals; the technical-details "Elapsed" has 3.
  - All of them go through `NUMBER` with an `ExactDecimal`. The unit is a literal in the message (`ms`, or `s`/`sn` via `hv-conn-unit-s`).
- **R17. Docker harness.**
  - `docker/m2a/compose.yml` and `docker/m2a/targets.toml`, with the services listed in Task 11.
  - Images use major tags. The resolved versions are recorded at the gate.
