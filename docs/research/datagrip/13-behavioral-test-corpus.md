# 13 — Behavioral Test Corpus for DataGrip 2024.3.5 (black-box, fill-in tables)

> Part of the Hacivat research library. Conventions: `../README.md`. This corpus pins down behavior that documents 06–12 could only infer, by *running DataGrip* — no decompilation. Every case has an ID referenced from the other documents (e.g. doc 06 ALG-SQL-01 → family SPLIT; doc 07 ALG-EXEC-01 → CARET; doc 08 → PASTE/CSV/WIDEN/DML; doc 09 → DDL; doc 11 → SET). The results become Hacivat golden tests (§4).

> **Status (2026-11-11): optional reference, not a blocker.** No case in this corpus gates a Hacivat design decision — DataGrip behavior is reference behavior, and Hacivat's own behavior is specified in `../algorithms/` from DBMS semantics, open-source prior art and our own design choices. Several cases have already been resolved from bundled help screenshots and YouTrack (e.g. CARET-02/03). Run cases only when parity with DataGrip is explicitly wanted for a feature.

---

## 1. Scope and sources

**What this is.** A runnable checklist for a non-expert operator: set up 5 databases in Docker (or a file for SQLite), load our own seed schema, reset DataGrip to defaults, then execute each case and write down what DataGrip did in the empty **Observed** column.

**What this is not.** Not a specification of correct SQL behavior — DataGrip's choices are recorded as *reference behavior*; Hacivat may deliberately differ (document such decisions next to the case).

**Sources for expected hints.** Offline help (DataGripHelp, Oct 2024), the settings index (doc 11), inspection/intention catalogs (doc 06), registry keys (doc 11 §3.13), class names (docs 06–10). Each hint is tagged **[Inferred]** unless the help states it (**[Observed: help …]**). All SQL in this document was written for this corpus; no shipped DataGrip resources are copied.

**Licenses.** Docker images used: PostgreSQL (PostgreSQL License), MySQL Community (GPLv2 — only run, not distributed), SQL Server Developer (Microsoft EULA — evaluation/dev use), Oracle Database Free (Oracle Free Use Terms), SQLite (public domain).

## 2. Executive summary

1. ~470 table cases (plus INTN-01..35) in 26 families: SET (defaults), SPLIT (statement splitting, 5 dialects), CARET (execution range), SEL (selection modes), CHOOSE (chooser), PARAM, TITLE, UNSAFE, RO, TX, ERR, COMPL, JOIN, ALIAS, QUAL, INSP, INTN, FMT, PASTE, CSV, WIDEN, DML, PAGE, FILTER, DDL, IMP/EXP/HIST/DUMP.
2. Each case: **ID | Dialect | Input | Steps | What to record | Expected hint | Observed | Notes**.
3. Inputs longer than one line live in fenced **fixtures** (`FX-…`) in §3.3 and are referenced by ID.
4. Caret positions are marked with `┃` (delete the mark before running; put the caret there). Selections are marked `«…»`.
5. Always record: DataGrip version/build (`243.24978.79`), dialect, data source, the *Output* pane text, and a screenshot when UI matters.
6. Reset protocol (§3.2) is mandatory: many behaviors depend on settings whose defaults we do not know (family SET).
7. §4 turns observations into automated Hacivat tests (snapshot format, harness, diffing).
8. Expected hints are guesses; wrong hints are valuable findings — mark them.

### 3.2 Reset and recording protocol

1. Start DataGrip with a **fresh config** (Help › "Change Memory Settings" is not enough): quit, rename `~/Library/Application Support/JetBrains/DataGrip2024.3` (macOS) to `…-backup`, start → defaults. Record the exact path in Notes of SET-00.
2. Language English (Settings › Appearance & Behavior › System Settings › Language and Region), New UI default.
3. After each case that changes settings, revert via the gear "Reset" link of that page.
4. Record: (a) copy of **Output** pane lines; (b) for executions, which statements ran (gutter marks + Output); (c) for grid edits, **Preview Pending Changes** text (Show Options Menu / toolbar) *before* submit, and the Output log *after*; (d) screenshots named `<ID>.png`; (e) completion: the top 10 items in order (copy names), the inserted text after Enter.
5. Write results into this file (Observed column) or a CSV with columns `id,observed,notes,screenshot`.

## 4. Algorithm specifications

### ALG-TEST-01: Running the corpus and converting observations into Hacivat golden tests
- **Problem:** Turn manual observations into machine-checked regression tests.
- **Inputs / outputs:** this document with Observed filled (or `observations.csv`), fixtures → `tests/golden/<family>/<ID>.yaml` + snapshot files.
- **Algorithm:**
  1. For each case, write a YAML record: `id`, `dialect`, `input` (inline or fixture ref), `context` (caret offset computed from `┃`, selection from `«»`, settings overrides), `datagrip_observed` (normalized text), `hacivat_expected` (initially = observed, or an explicit divergence with `reason`).
  2. Normalize observations: trim whitespace, normalize line endings, replace volatile parts (timings `in \d+ ms` → `in <ms>`, timestamps, generated names) with placeholders.
  3. Map families to test harnesses: SPLIT/CARET/SEL → `sql-split` unit tests (no DB); COMPL/JOIN/ALIAS/QUAL → language-service tests with a catalog fixture (`seed` schema snapshot as JSON); INSP/INTN/FMT → snapshot tests with `insta` (Apache-2.0/MIT) per dialect; PASTE/CSV/WIDEN → pure function tests with byte fixtures; DML/PAGE/FILTER/UNSAFE/RO/TX/PARAM → integration tests against Docker databases (testcontainers-rs, MIT) asserting generated SQL text and DB effects; DDL → diff+schedule tests comparing generated scripts and executing them on fresh containers (apply then compare models = zero diff).
  4. CI matrix: unit families on every commit; DB families nightly with containers (PG 16, MySQL 8.4, MSSQL 2022, SQLite; Oracle optional).
  5. Divergence register: a table listing cases where Hacivat intentionally differs (e.g. bind parameters by default, keyset paging, optimistic concurrency) with rationale.
- **Edge cases:** observations depending on IDE timing (async completion); flaky ML ranking order (record top-3 set, not exact order, when ML ranking is on — or disable ML in SET-08 for deterministic order); locale-dependent display (run with English UI and `en_US` JVM locale except Turkish cases).
- **Test cases:** this corpus.
- **Used by:** Hacivat.

### ALG-TEST-02: Differential oracle harness (Hacivat vs DataGrip vs DBMS)
- **Problem:** Some answers have a ground truth beyond DataGrip (e.g. splitting must match what the DB executes).
- **Algorithm:** for SPLIT cases, additionally run the full script through the native CLI (`psql -v ON_ERROR_STOP=1 -f`, `mysql < file`, `sqlcmd -i`, `sqlplus @file`, `sqlite3 < file`) and capture executed statements (PG: `log_statement=all` in the container and read logs; MySQL: general log; MSSQL: Extended Events/profiler; SQLite: `sqlite3_trace_v2` via a tiny harness); compare statement boundaries: Hacivat splitter vs DB-observed vs DataGrip-observed; disagreements are triaged (DataGrip bug, Hacivat bug, client-tool semantics).
- **Edge cases:** client-side commands (DELIMITER, GO, psql meta) never reach the server — compare against tool semantics; servers rewriting statements in logs.
- **Used by:** Hacivat; Karagöz (same harness validates server-side statement classification).

## 5. Implications for Hacivat

- Treat this corpus as the acceptance suite for v1 editor/execution/grid features; each family maps to a crate (doc 06/07/08/09 §5).
- Decide divergences early: bind parameters (PARAM), keyset paging (PAGE), optimistic concurrency and affected-row checks (DML-18..20), redaction in history (HIST-03), secure credential passing for dump tools (DUMP-02).
- Keep the seed schema as the canonical fixture for MCP tool tests too (agents must be able to answer "join orders to customers" deterministically).

## 6. i18n considerations

- Turkish cases are marked "Turkish" in Notes: dotted/dotless I in identifiers and keyword upper-casing (FMT-09/10), Turkish text in literals (DML-25, EXP-02), Windows-1254 CSV (CSV-07), decimal comma/semicolon CSV (PASTE-05, WIDEN-13), Turkish dates (PASTE-24), case-insensitive find (FILTER-10), Turkish identifiers in completion/aliases (COMPL-32, ALIAS-07), Unicode parameter names (PARAM-18).
- Run the Turkish cases twice: with JVM default locale `en_US` and with `-Duser.language=tr -Duser.country=TR` (add to `datagrip.vmoptions`) to detect locale-sensitive case mapping bugs; Hacivat's equivalents must pass under `LANG=tr_TR.UTF-8`.
- Record UI text only in English for comparability; the localized UI is irrelevant for behavior.

## 7. Risks, pitfalls, open questions

- Manual execution effort is large (~470 cases); prioritize: SPLIT, CARET, DML, UNSAFE, PARAM, PASTE, CSV (they drive v1 safety and correctness), then COMPL/JOIN, then FMT/DDL.
- Some behaviors depend on DataGrip internals that may change in later versions; record the build number with every observation.
- Oracle container is heavy (~2–3 GB RAM); optional.
- Running read-only/transaction cases against shared databases is risky — only use the disposable containers above.
- Open: whether DataGrip logs all generated SQL (paging, filters) in the Output pane by default; if not, use server-side statement logging (PG `ALTER SYSTEM SET log_statement='all'` in the container) to capture it.
